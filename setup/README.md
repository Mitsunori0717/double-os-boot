# Edge Box の一括・番号別セットアップ

新しい PC でも、途中まで設定済みの PC でも同じバッチを使います。
Windows 11 Pro / Enterprise / Education と、FSBP が既に入った Edge Box の物理ディスクが必要です。
FSBP のインストール、アプリの接続先 IP の入力、メーカー固有の設定はこの一式には含みません。

## 最初に実行するもの

一式をローカルディスクへ展開し、ルートの `setup-all.cmd`（またはこのフォルダの `setup-all.cmd`）をダブルクリックします。
UAC を許可し、作業を保存して Enter を押すと、実際の設定を確認して未完了の手順だけを適用します。
複数のディスク・LAN 候補がある場合だけ選択し、自動サインインが未設定ならパスワードを入力します。
パスワードや PIN を設定ファイル・コマンド引数・ログへ保存することはありません。パスワードは Windows の LSA 秘密領域へ保存します。

一括実行は必要な場合に PC を通常の方法で再起動します。再起動後は同じユーザーのサインイン時に一時タスクが最高権限で続行します。
自動サインインが未設定なら最初のサインインは手動です。自動再起動は最大 2 回で、再起動しても同じ設定が反映されない場合は停止して原因を表示します。
一時タスク `EdgeBox-Setup-Resume` は完了・再起動を要しない失敗時に削除します。

## 番号別にやり直す

ログに書かれた番号のバッチをダブルクリックしてください。前提の設定が足りない場合は、その番号も案内します。
番号別は自分の手順だけを実行し、PC を自動で再起動しません。「再起動待ち」が出たら通常の再起動を行ってください。
ここでの番号はこの表を基準にします。`windows-host` 内のスクリプトの番号とは異なります。

| バッチ | 設定・確認する内容 |
|---|---|
| `02-enable-hyperv.cmd` | Hyper-V の機能、稼働中のハイパーバイザー、管理サービス |
| `05-create-edgebox.cmd` | 既存 VM の検出、物理ディスク、外部 LAN、正常終了・起動構成 |
| `06-auto-logon.cmd` | 自動サインイン（必要な場合だけパスワード入力） |
| `09-install-autostart.cmd` | VM の自動起動、左画面表示、専用の起動中画面 |
| `10-partition-cpu.cmd` | CPU の完全分離、BCD、起動タスク、今回の起動での CPU グループ所属 |
| `11-install-shortcuts.cmd` | 操作用アイコンと管理者タスクの配置先 |
| `12-windows-update.cmd` | 既存の更新抑止スクリプトによる自動更新・再起動の抑止 |
| `13-quiet-windows.cmd` | 既存の通知・スリープ抑止スクリプトによる常時稼働設定 |
| `check-status.cmd` | 状態を読むだけ。設定・ログ・進捗ファイルは変更しません |

確認モードで「確認不能」になる場合は `check-status.cmd` を右クリックして「管理者として実行」してください。
一括で再起動を自動実行したくない場合は PowerShell から `powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-all.ps1` と実行します。

## 失敗時のログ

`setup\logs\日時-実行ID\` を開きます。

- `summary.txt`: 手順ごとの状態、原因、対処法、再実行するバッチのフルパス。
- `results.json`: 同じ結果を番号・状態・原因・対処法・再実行先に分けて保存。
- `番号-スクリプト名.txt` / `.stderr.txt`: 子スクリプトの詳しい出力。

状態は「設定済み」「未設定・修復必要」「再起動待ち」「前提未達」「確認不能」「失敗」です。
子スクリプトの終了コードが 0 でも、設定を読み直して確認できなければ成功と扱いません。
失敗しても依存しない手順は続行します。権限不足などで状態を読めない場合は、未設定と決めつけて上書きしません。
再実行すると進捗ファイルの成功記録を信用せず、実環境をもう一度確認します。
終了コードは全完了 `0`、未完了・失敗 `1`、確認モードで未完了あり `2`、要再起動 `3010` です。

ディスクは起動用・システム用・USB・ドライブ文字のある候補を自動選択から除きます。
選択はディスクの一意 ID と LAN の GUID で `settings.json` に記録し、再起動後に番号が変わっても追従します。
選択済みの機器が見つからない場合、別の機器に勝手に切り替えません。別 VM のディスク接続も自動で外しません。
`settings.json` は端末固有です。別 PC へはコピーせず、配布 ZIP / EXE を使ってください。

CPU の既存計画は引き継ぎます。新規では CPU 自身が返す物理コア構成を使い、混成 CPU は末尾の E コア（最大 8 個）、同種コアは後半を Edge Box に割り当てます。
既定計画で Edge Box 8 論理 CPU・Windows 4 論理 CPU を確保できない機種や、確実に構成を検出できない機種は、自動適用を保留します。
「CPU割り当て」で機種に合った計画を適用してから `10-partition-cpu.cmd` を実行してください。
Windows クライアント版で CPU グループが使えない場合も「完全分離できた」とは表示せず、ログで案内します。

更新を手動で実施する場合は `windows-host\12-windows-update.ps1 -UpdateNow`、更新抑止を解除する場合は同じスクリプトの `-Restore`、通知・電源を戻す場合は `windows-host\13-quiet-windows.ps1 -Disable` を使います。

## 開発時の検証

Windows PowerShell 5.1 から `powershell -NoProfile -ExecutionPolicy Bypass -File setup\tests\run-tests.ps1` を実行します。
模擬環境と無害な子プロセスを使い、実際の VM・BCD・電源は変更しません。
