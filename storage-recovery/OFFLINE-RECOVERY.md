# オフラインでOS全体を取得・復元する実作業ルート

## 対応範囲

この文書は **Clonezilla Live の対話式取得という別方式**です。未使用領域も含む全LBA RAW取得と別PCのVM化は [新しい一連の経路](RECOVERY-PIPELINE.md) を使用してください。Windows PowerShell部分は物理ディスクを読み出し・書き込みしません。メーカー専用 Edge Box の起動・認証・ファイルシステム適合性は未検証であり、成功保証ではありません。

Clonezillaのイメージは通常、複数の圧縮ファイルとパーティション情報を含むディレクトリです。`StorageRecovery.psm1` の単一通常ファイル＋独自manifest形式とは別物です。`Test-RecoveryImage` でClonezilla形式を検証したり、このモジュールでClonezilla形式を復元したりできません。

## 準備するものと未解決条件

- 正常な元SSD、バックアップ保存用の別SSD、Live起動用USB、後日の復元試験用SSD。起動USB・保存SSD・復元先を混同しない。
- 保存SSDは元SSDの全容量を格納できる空きを確保する。圧縮率は保証しない。同じ「1TB」表記でも実バイトが不足する場合がある。安全側では2TBクラスを検討する。
- 接続変換器が必要なら元/先SSDの実インターフェース（NVMe/SATA等）に適合させる。USB変換でシリアルが欠落する場合はラベルと接続位置を照合し、曖昧なら停止する。
- Hyper-V管理者権限で現行VM設定、物理ディスク割当、MAC（動的/固定）、VM ID、CPU/メモリ、世代、UEFI設定、仮想スイッチを取得する。ホストNICのMACとゲストNICのMACを分ける。
- 暗号化がある場合の回復キー、Edge Box の正式な復元/移行条件、ハードウェア/ライセンス紐付けを確認する。秘密は公開ログ・Gitへ保存しない。
- Edge Box の正常終了とWindowsホスト停止でデータ収集が止まる。予定停止時間を確保する。Saved/Paused/休止/高速スタートアップではなく完全停止が必要。

## 信頼できる起動媒体

[公式ダウンロード](https://clonezilla.org/downloads.php)からstableの対応アーキテクチャを選ぶ。ISO、同じリリースのchecksums、checksums gpgを取得する。バージョンやミラーを混在させない。公式ページの鍵指紋と公式の署名確認手順でchecksumsの真正性を確認したうえで、該当ISOのSHA-256を照合する。ハッシュだけが一致しても、期待値の入手元が不明なら真正性は確認できない。

```powershell
Import-Module .\StorageRecovery.psm1
Test-RecoveryMediaHash -IsoPath 'E:\Downloads\clonezilla.iso' -ExpectedSha256 '<公式署名確認済みchecksumsの64桁SHA256>'
```

[公式Live媒体の作成手順](https://clonezilla.org/clonezilla-live.php)に従う。USBへの書込は内容を消すため、対象USBを特定してから行う。このプロジェクトはUSB作成、BIOS/セキュリティ設定変更、再起動を自動実行しない。

## 取得

1. 停止前に構成を記録し、対象ディスクをモデル・シリアル・実バイト・セクタサイズ・パーティション構成で識別する。ディスク番号だけを引き継がない。
2. 承認された保守時間にゲストを正常終了し、Offを確認してからホストを完全停止する。終了できなければ強制終了せず中断する。
3. Live USBで起動する。Windows/Hyper-Vからの書込みがない状態を確立する。元SSDをマウントしない。
4. [公式保存手順](https://clonezilla.org/show-live-doc-content.php?topic=clonezilla-live/doc/01_Save_disk_image)の `device-image` → `local_dev` → 保存SSDの領域 → `savedisk` を利用する。OSパーティションだけの `saveparts` ではなくディスク全体を選ぶ。
5. Linuxの `/dev/sda` 等は例にすぎない。今回の実ディスクを再照合し、保存先が元SSDでないことを確認する。初期化/修復/サイズ変更の追加操作は行わない。読取りエラーを無視して成功扱いにしない。
6. 保存後のイメージ検査を有効にする。正常終了、検査結果、対象、保存日時、Clonezillaバージョンと実行ログを保管する。Clonezillaで使用した画像名と保存先を記録する。失敗・中断分は未完成として区別する。
7. 保存SSDを別の故障領域へ保管し、機密保護する。さらに別コピーを用意する。現行PCの内蔵C:のみへの保存ではPC故障対策にならない。

## 他PCでの復元試験

1. 元SSDと唯一のバックアップを上書き対象にしない。必要なら物理的に取り外して保護する。試験先は破壊してよい専用SSDとする。
2. 復元先の実バイト容量が元以上、論理セクタサイズが互換であることを確認する。縮小/セクタ変換は初版の対象外。交換先ホストの仮想化機能、世代、接続機器の互換性も確認する。
3. [公式復元手順](https://clonezilla.org/show-live-doc-content.php?topic=clonezilla-live/doc/02_Restore_disk_image)に従い `restoredisk` を使用する。保存イメージを事前検査し、復元先の消去範囲を目視で再確認する。自動承諾フラグは使わない。
4. 元VM/元機器を停止またはネットワークから切り離したまま、復元側を隔離ネットワークで試験する。重複MAC/IP・二重データ収集・工作機械への意図しない接続を防ぐ。
5. Hyper-V構成の再作成、MAC/ID保持の必要性、Edge Box 認証を確認する。MACを一致させるだけでライセンスが移るとは扱わない。必要ならメーカーの正規再発行/移行を使う。
6. OS起動、Edge Box 画面、ライセンス、保存設定/データ、必要機能を確認して初めて `restore-tested` とする。イメージ検査だけではこの状態にならない。工場ネットワークへ戻すのは別の確認工程。

## 自動化する範囲

このClonezilla別方式の自動化は構成収集・事前判定・ISOハッシュ照合・通常イメージファイル複製の検査まで。実機検証後に、Live環境からのディスク識別と保存先照合を追加する余地はあるが、未検証の生ディスクコマンドや番号固定のバッチは生成しない。NAS/ネットワーク転送、差分VHDX、RAID、障害ディスクの救出、暗号化解除、ハイパーバイザ移行は別評価とし、未知条件では止める。

### 保存方式と構成台帳の限界

Clonezillaの `savedisk` はディスク全体を復元対象にしますが、対応ファイルシステムでは使用中ブロック中心に保存します。[公式の方式説明](https://clonezilla.org/)の通り、未使用領域を含む全LBAのビット単位複製とは区別が必要です。Edge Box の未知の認証領域を含め、全セクタ保全が必要な場合はメーカー条件と実機方式を別途検証し、この手順だけで完全な生イメージ取得済みとはしません。

`Get-RecoveryInventory` は補助台帳であり、完全なVMエクスポートではありません。新版は起動順序、第1世代BIOS、VLAN、TPM状態も収集しますが、秘密鍵や完全なVM構成を保存するものではありません。復旧前にはHyper-V管理者による追加確認と正規の構成保全が必要です。
