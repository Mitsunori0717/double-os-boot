# Windows / Linux 同時稼働システム — 説明資料

## 一言でいうと

**1台のPCで Windows と Linux を同時に動かし、2枚のモニターに分けて表示するシステム**です。
工場ラインのデータ収集(Linux 上の EdgeBox)と、その分析・操作(Windows 上の専用アプリ)を
PC 1台に集約し、両者は PC 内部で直接データ連携します。

```
        ┌──────────────── 1台のPC ────────────────┐
        │                                          │
   モニター1                                   モニター2
 ┌──────────────┐                        ┌──────────────┐
 │   Windows     │  ← PC内部で直接連携 →  │    Linux      │
 │ (EdgeBox 専用アプリ)│    (ネットワーク直結・     │ (EdgeBox 本体:    │
 │  メイン業務     │     共有フォルダ)        │  ラインのデータ │
 │               │                        │  収集ロガー)   │
 └──────────────┘                        └──────┬───────┘
                                                │
                                          工場ラインの工作機械
```

## 概要

### 1. 方式 — 「仮想化ソフトの画面の中で動かす」方式ではない

一般的な仮想化(VirtualBox 等)は、Windows のウィンドウの中に Linux の画面を「絵として」
表示する方式で、性能が落ち、不具合時にどの層の問題か切り分けできない欠点があります。

本システムは **ハードウェア分割方式** です。PC の実物の部品(CPU コア・メモリ・GPU・ディスク)
を 2 つの OS に**分割して直接割り当て**ます。それぞれの OS は割り当てられた実物の部品を
自分専用のハードウェアとして直接制御します(詳細は「原理」参照)。

### 2. 起動方法 — 用途に応じて2通り

| モード | 起動方法 | 用途 |
|---|---|---|
| **単独起動** | 電源ON → 起動メニューで Windows か Linux を選択 | 従来どおりの使い方。切り分け作業・確実性最優先の作業 |
| **同時起動** | Linux を起動 → コマンド1つで Windows が隣のモニターに起動 | 日常運用。収集と分析を同時に行う |

どちらのモードでも **ディスクの中身は同一** です(C: の Windows、D: の Linux をそのまま使用)。

### 3. 画面 — 2枚のモニターにそれぞれの OS

- モニター1 = Windows。**Windows 専用の GPU(グラフィックボード)から直接出力**。
  画面転送やリモートデスクトップではないため、表示品質・応答はネイティブと同一
- モニター2 = Linux(EdgeBox の稼働状況を常時監視できる)
- キーボード・マウスは 1 組を共用し、キー操作(左右 Ctrl 同時押し)で操作先を切替

### 4. データ連携 — EdgeBox ⇔ Windows アプリ

- PC 内部に **外部 LAN を経由しない OS 間直結の内部ネットワーク**(遅延 1ms 未満)があり、
  Windows の EdgeBox 専用アプリはこの経路で Linux 上の EdgeBox 本体に接続します
- ファイルの受け渡し用に **共有フォルダ**(両 OS から同じフォルダが見える)も用意
- 収集データが PC の外に出ない閉じた経路のため、セキュリティ面でも有利

## 原理 — ハードウェアの分割

搭載ハードウェアを以下のように 2 つの OS に割り当てます(割り当ては後から変更可能)。

```
┌─────────────────── PC のハードウェア ───────────────────┐
│                                                         │
│  CPU (i7-14700: 20コア/28スレッド)                        │
│  ├── 高性能コア6個 + 高効率コア8個 (20スレッド) → Windows   │
│  └── 高性能コア2個 + 高効率コア4個 (8スレッド)  → Linux     │
│                                                         │
│  メモリ (例: 32GB)                                       │
│  ├── 16GB → Windows (物理的に確保・相互不可侵)             │
│  └── 16GB → Linux                                       │
│                                                         │
│  GPU × 2系統                                             │
│  ├── GPU 1 (メイン) → Windows 専有 → モニター1へ直接出力    │
│  └── GPU 2 (内蔵/ロープロ) → Linux → モニター2へ直接出力    │
│                                                         │
│  ディスク × 2本 (物理的に別のドライブ)                      │
│  ├── ディスク1 (C: Windows) → Windows 専有                │
│  └── ディスク2 (D: Linux)   → Linux 専有                  │
└─────────────────────────────────────────────────────────┘
```

- **CPU の分割**: コア単位で固定割り当て。Windows 用コアの上では Windows の命令が
  CPU 上で直接実行される(性能按分ではなく物理分割。互いのコアには載らない)
- **メモリの分割**: 起動時に物理的に確保し、相互に侵食しない。Windows が重くなっても
  EdgeBox のデータ収集がメモリ不足に巻き込まれることはない(逆も同じ)
- **GPU を 2 つ**: 各 OS が実物の GPU を 1 系統ずつ専有し、自分のモニターへ直接出力
- **物理ストレージも 2 つ**: 1 本のディスクをパーティションで分けるのではなく、
  物理的に別のドライブ 2 本 (C: 用と D: 用) を各 OS が専有。同時アクセスによる
  データ破損の可能性を構造的に排除し、通常起動時と全く同じディスクの姿を保つ

### 正確な技術的位置づけ(質問された場合の回答)

「2 つの OS が 1 つの CPU を仲介なしに同時所有する」ことは計算機の構造上不可能です。
本システムでは、ハードウェアの割り当てを管理する**ごく薄い調停層**(Linux 標準機能の KVM)が
動作しますが、その役割は「どの部品をどちらの OS が所有するか」の交通整理のみで、
GPU・ディスク・CPU 命令の実行はすべて実物のハードウェアが直接行います。
実測性能はネイティブ比 95〜98% です。

さらに、**単独起動モードでは調停層すら存在しない完全な素の状態**で起動できるため、
ソフトに不具合が出た場合は「単独起動で再現するか」を確認するだけで、
Windows/ソフト自体の問題か、調停層の問題かを**機械的に切り分けられます**。
(従来の仮想化ソフト方式ではこの切り分けが原理的にできません)

## 導入メリットのまとめ

| 観点 | 効果 |
|---|---|
| 省スペース・コスト | PC 2台分の役割を1台に集約。モニター・設置場所・保守対象を削減 |
| 業務効率 | データ収集(Linux)を止めずに、隣の画面で分析・操作(Windows)ができる |
| 信頼性 | 資源が物理分割されているため、片方の高負荷が他方(特にライン収集)に波及しない |
| 保守性 | 不具合時に問題の層を機械的に切り分け可能。資源配分は運用しながら調整可能 |
| セキュリティ | EdgeBox と Windows アプリの通信が PC 内部で完結し、収集データが外部 LAN に出ない構成も可能 |

## 必要なハードウェア・制約

- CPU: ハードウェア分割支援機能(VT-x/VT-d)対応 — **i7-14700 は対応済み**
- GPU: 2 系統(メイン GPU + CPU 内蔵グラフィックスまたはロープロファイル GPU)
- ディスク: Windows 用と Linux 用で物理的に別のドライブ 2 本
- メモリ: 32GB 推奨
- 制約:
  - Windows のライセンスは初回に再認証が 1 回必要(デジタルライセンスで対応可能)
  - 同時起動中は決められた手順でのみ操作する運用ルールあり(手順書・スクリプト整備済み)

## 起動とシャットダウンの流れ

### 起動

1. PC の電源を ON → Linux が起動し、EdgeBox がライン収集を開始(モニター2)
2. コマンド 1 つ実行 → Windows がモニター1 に起動(約 30 秒。以後は両画面を同時に使用)

### シャットダウン

1. Windows をスタートメニューから通常どおりシャットダウン
   (Linux 側の収集は継続。Windows 用メモリは自動で Linux に返却)
2. Linux をシャットダウン → PC の電源が切れる

単独起動モード (Windows または Linux を 1 つだけ使う) の場合は、通常の PC と同じ操作です。
