# 実機受入手順

この文書の項目は未実施です。開発テストの合格から実機成功へ自動昇格しません。記録には実施日時、使用した配布 ZIP の SHA-256、対象媒体の識別情報、担当者、各結果を残し、回復キー・パスワード本文は記載しません。

## セットアップ

| 確認 | 合格条件 |
|---|---|
| 対象の一致 | 選択した VM ID、ディスク UniqueId / serial / 容量、LAN が実機と一致 |
| 再実行 | 設定済み手順で不要な変更をせず、異なる機器を接続すると停止 |
| 正常停止 | Edge Box が正常終了し、停止確認後だけホストが終了。停止失敗時はホストを維持 |
| 再起動後 | 自動ログオン・表示・VM 起動・CPU 分離を実測し、保存された計画と一致 |
| 業務機能 | Edge Box の画面、保存データ、認証、必要な機器認識が期待どおり |

## 取得・物理復元

1. 元媒体を正常停止し、専用 Live 環境で kernel read-only、未マウント、独立ディスク構成を確認します。
2. RAW と manifest を別媒体へ保存し、全量 SHA-256 とサイズを検証します。複数媒体なら静止期間と全依存媒体を記録し、セット検証を行います。
3. 元媒体から分離した消去可能な予備 SSD で、計画と表示されたシリアル・容量を照合します。同容量復元、大容量適応は別の試験として記録します。
4. 全量書戻し・flush・読み戻しの一致を確認します。大容量適応ではパーティションを拡張しないこと、GPT の末尾情報と余剰領域が期待どおりであることを確認します。
5. 元媒体を接続しない状態で復元先を起動し、OS、アプリ、設定、データ、認証を確認します。途中 I/O 失敗の試験は消去可能な媒体だけで行い、失敗を成功扱いしないことを確認します。

## 隔離 VM 復旧

1. 原本・変換 VHDX・稼働コピーの格納場所を分離し、十分な空き容量を確認します。
2. 作成計画の全ディスク・世代・CPU・RAM・Secure Boot・vTPM・ID変更条件を確認します。
3. `-Create` で停止状態の新規 VM を作成し、全接続先が稼働コピーで、物理ディスクやネットワークへ未接続であることを確認します。
4. `-StartIsolated` による初回起動後、必要なら正規回復手段で手動解除し、OS・アプリ・データ・認証を個別に確認します。旧 TPM の秘密は新 vTPM に移行しません。
5. 失敗時は `recovery-failure.json` とログから残存 VM・コピー・工程を確認します。既存フォルダーへ再実行せず、原因を解消して新しい保存先を使います。

業務ネットワークへの接続はこの受入の後に実施する独立工程です。重複する IP・MAC、工作機械への通信、メーカーの利用条件を確認します。
